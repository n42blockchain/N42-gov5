# N42 Verifier Android Sample — Build Guide

## Prerequisites

- Android Studio Hedgehog (2023.1.1) or later
- Android SDK Platform 34 + Build Tools 34.0.0
- Android NDK 25.2.9519653 (the version in `Makefile`'s `android` target)
- Go 1.21+
- gomobile installed:
  ```bash
  go install golang.org/x/mobile/cmd/gomobile@latest
  go install golang.org/x/mobile/cmd/gobind@latest
  gomobile init
  ```

Set the env vars before invoking `make android`:

```bash
export ANDROID_HOME=$HOME/Android/Sdk
export ANDROID_NDK_HOME=$ANDROID_HOME/ndk/25.2.9519653
```

## 1. Build the gomobile bind

From the N42-gov5 repo root:

```bash
make android
# or, equivalently:
CGO_ENABLED=1 \
ANDROID_HOME=$ANDROID_HOME \
ANDROID_NDK_HOME=$ANDROID_NDK_HOME \
  gomobile bind -tags nosqlite,noboltdb \
    -androidapi 24 \
    -o build/mobile/android/evmsdk.aar \
    -target=android/arm64 \
    github.com/n42blockchain/N42/cmd/evmsdk
```

This produces `build/mobile/android/evmsdk.aar` (typically 30-40 MB).

For multi-architecture builds, pass `-target=android/arm64,android/arm`
or `android` for all architectures (slower; larger output).

## 2. Drop the .aar into the sample app

```bash
mkdir -p cmd/evmsdk/sample-android/app/libs
cp build/mobile/android/evmsdk.aar cmd/evmsdk/sample-android/app/libs/
```

The Gradle script in `app/build.gradle.kts` already references
`files("libs/evmsdk.aar")` as an `implementation` dependency.

## 3. Open in Android Studio

```bash
# Open the sample-android directory in Android Studio
studio cmd/evmsdk/sample-android
```

Android Studio will prompt for missing Gradle wrapper / settings files
on first open. Accept its defaults (sync to current Gradle version).

The minimum required project structure:

```
cmd/evmsdk/sample-android/
├── app/
│   ├── build.gradle.kts            # provided
│   ├── libs/
│   │   └── evmsdk.aar              # you copied this in step 2
│   └── src/main/
│       ├── AndroidManifest.xml      # provided
│       └── java/io/n42/verifier/
│           ├── EvmsdkWrapper.kt     # provided
│           └── MainActivity.kt      # provided
├── settings.gradle.kts              # generated by Android Studio
└── build.gradle.kts                 # generated by Android Studio
```

## 4. Run

Connect a device with USB debugging enabled (or pick an emulator) → Run.

The app will:

1. Call `Evmsdk.mobileInit(4242L)` on launch → status "Initialized"
2. Wait for you to enter a 64-hex-char BLS private key → "Set Key"
3. Wait for you to enter the IDC server host/port and verifier account
4. "Start" → calls `Evmsdk.mobileSetServer` then `Evmsdk.mobileStart`
5. A coroutine polls `Evmsdk.mobileGetStats()` and
   `Evmsdk.mobileGetLastVerifyInfo()` every 1s, updates the Compose
   `StateFlow` bindings → real-time stats display

## 5. Troubleshooting

### `evmsdk.aar` is too big

Production builds should use `-tags nosqlite,noboltdb` (the Makefile
already does this). If you still hit AAR size limits, consider stripping
debug symbols:

```bash
gomobile bind -tags nosqlite,noboltdb -ldflags="-s -w" ...
```

### `java.lang.UnsatisfiedLinkError: dlopen failed`

The .aar was built for the wrong ABI. Rebuild with `-target=android/arm64`
for modern devices, or build a multi-arch aar:

```bash
gomobile bind -target=android/arm64,android/arm,android/amd64 ...
```

### Gradle sync fails on first open

Android Studio expects a `settings.gradle.kts` and a top-level
`build.gradle.kts`. The minimal versions are auto-generated when you
"Sync Project with Gradle Files" — accept the default scaffolding.

### Status stuck at "Connected" but no blocks verified

The IDC node's WebSocket subscriber service is not yet wired into the
N42-gov5 main binary (Phase 2b — pending). Until it lands, use offline
mode: pass packet bytes to `Evmsdk.mobileVerifyPacket(_:)` directly.
See `cmd/evmsdk/mobile_facade_test.go::TestMobileFacade_StatsAfterVerify`
for the calling pattern.

## 6. Notes

- **Min SDK 24** (Android 7.0) — matches the `-androidapi 24` flag in
  the gomobile bind command
- **Compose Material 3** with `compose-bom:2024.02.00`
- **Backgrounding behavior**: Android may suspend gomobile goroutines
  when the app is backgrounded. Production apps should call
  `verifier.stop()` from `Activity.onPause()` and restart on
  `onResume()`.
- **Battery**: continuous parallel verification uses the EVM execution
  pipeline on every committed block (typically 12s on a real chain),
  so power draw is non-trivial. Consider exposing a "verify N blocks
  per minute" throttle in production apps.

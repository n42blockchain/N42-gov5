# Post-bounded failed-drain audit

This runner performs two physical reopens of the same retained runtime with ordinary strict ingress, seven validators configured with `miner=false`, and zero transaction dispatch. Each wrapper pins an already accepted clean binary set; the audit requires no Go change, initialization, source scan, old session arming or pending-transaction reinjection.

The failed candidate and all 64 receipt journals stay immutable. The parser now accepts exactly two failure strings: the original acknowledged-prefix drain deadline, and `Post "http://unix/v1/status": context deadline exceeded`. The latter is the actual q6 drain-stage validator status error, not an admission acknowledgement error; it may reflect the remaining overall drain deadline and does not establish deadlock. Unknown HTTP errors still fail. Both cases require independently sealed failure and release evidence, complete journals and sender increments, a nonregressing last reference, and canonical lower/ACK upper bounds. The original error is never rewritten to fit the older schema.

Q6 remains failed, sealed `8207c19c`. Its 489,000 canonical transactions over 20.007302757 seconds (24,441.075638/s) are diagnostic only. The last reference is height 1431/count 7,570,852; known 2,395,648 new ACK admissions over baseline 5,940,852 give upper bound 8,336,500. Pending 765,648 is only a sampled queue value, not a final lost or persisted count. Ordinary reopens must determine final head/root/vector, without assuming observed execution of a later block became durable or canonical. The accepted 545ec715 binary set may be reused by a separately reviewed audit wrapper; no such audit has run for q6 yet.

The first fresh complete 6000-account/root snapshot must lie between the last reference and baseline plus known ACKs. Each sender nonce is bounded by its exact acknowledged increment, with the 21001-wei per-transfer balance change, unchanged code/existence and header root equal to loaded QMDB root. The second physical reopen must match the first full head/root/vector with a new epoch.

A runtime90 BOX claim wraps both reopens and full four-file PRE/POST observations. Original path/device/inode/mode stay fixed while a fresh PRE SHA is bound to the sealed failure stat; three protected copies stay byte-identical. All 18 processes, nine sockets and owned claims must cleanly exit before promotion. Any actual failure freezes without replay or automatic recovery-only switch. This audit creates no new TPS claim.

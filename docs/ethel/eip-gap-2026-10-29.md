## Open gaps, by risk

### P1 — invalid-block rejection and data checks (canonical chain unaffected)

1. **Osaka per-tx / per-block validity only on the newPayload path.** (7825 fixed in `f26b1b2d`.) EIP-7825 (tx gas cap 2^24),
   blob-tx shape (to != nil, >= 1 blob, version byte, <= 6 blobs per tx) and EIP-7934 (8 MiB RLP
   cap) are enforced in `validateExecutionPayloadTransactionsWithBaseFee` only; devp2p
   `ImportSyncedBlock`, batch replay and the miner skip them, and `EthReplayEngine.VerifyHeader`
   is a no-op. geth checks 7825 in `preCheck`. Moving it into `state_transition` changes N42's own
   chains too wherever Osaka is active, so first check their history for transactions above
   16,777,216 gas, or gate on the Ethereum chain only.
2. **Batch replay does not check `requestsHash`, receipts root or bloom** (`internal/ethel/process.go`);
   only gasUsed and the periodic state root.
3. **EIP-7702 `auth.V` truncated to uint64** — y_parity >= 2^64 is accepted where geth fails decode.
4. **EIP-4788 written as a direct storage write**, also when the contract has no code, and a missing
   `parentBeaconBlockRoot` after Cancun is skipped instead of rejected. Correct on mainnet; wrong on
   hive / test chains.
5. **EIP-6110 deposit contract address hard-coded to mainnet** (wrong for any other network).

### P2 — interoperability

6. **EIP-7594 EL side missing**: no blob-tx wrapper v1 (cell proofs), txpool verifies v0 proofs only,
   no `engine_getPayloadV5` / `engine_getBlobsV2`. Following with newPayloadV4 works; building Osaka
   blocks for a real CL or serving blobs to it does not.
7. **Engine API**: fork-range checks are skipped because `PectraTime` is nil on mainnet (gates on
   `IsPectra` should be `IsPrague`); FCUv4 is a non-standard variant; capabilities lack Osaka.
8. **EIP-7910 `eth_config` not implemented.**
9. **eth/70 and eth/71 advertised but not implemented to spec**: EIP-7975 partial receipts are
   missing, GetReceipts is not served, and the eth/71 BAL messages carry N42's BAL format. Sync only
   fetches headers and bodies, so following is unaffected; either implement them or stop
   advertising 70/71. geth speaks 69-72 and has dropped 68.

### P3 — Glamsterdam readiness (blocked on decisions)

10. **Header slot conflict** (fixed in `65f2c63f`): EIP-7843 adds `slot_number` at header RLP position 23, which N42 uses
    for `MobileRegistryRoot`. The eth-el header encoding has to diverge from N42's own chains there,
    and every codec (RLP, trailer, compact) must carry it.
11. **EIP-7928 BAL**: N42's BAL is its own format (writes only, keyed by tx hash), gated on a separate
    `BALTime`; the spec BAL (reads, system-call writes, `blockAccessListHash`) is not implemented.
12. **`IsGlamsterdam` implies `IsFusaka`**, which pulls N42-private features (native AA, the 7907
    stub) into an Ethereum fork. Glamsterdam gas constants (2780/7976/7981/8037/8038) are drafts not
    checked against Amsterdam EEST; 8037/8038 may still change after the ChainSecurity review.
13. EIP-7732 ePBS EL side (newPayloadV5 / getPayloadV6), 7708, 7778, 8024, 8246, 8282 to be ported
    from erigon (`execution/protocol/misc/eip7708.go`, `eip8282.go`, `execution/vm/eips.go`,
    `execution/bal/`) once the mainnet date is set.

### Test coverage

EEST / hive fixtures are not wired (`tests/eth_test_runner_test.go` skips; last results 2026-03).
The weekly mainnet replay validates state-affecting rules on canonical blocks only, not rejection
of invalid blocks. Wiring the EEST state and blockchain fixtures for Cancun -> Osaka is the
cheapest way to find the rest of the P1 class.

### SLOTNUM empty-stack panic on N42 chains (fixed in `e25885f7`)

Found while porting D2. On an N42 chain where Fusaka is active (qs staggered, mainnet chainspec),
the N42 Fusaka form of SLOTNUM (0x4b) peeked the stack without a length check, so an empty stack
panicked with a nil dereference. A creation transaction whose initcode is the single byte `4b`
triggered it: the miner recovered the panic but kept the transaction in the pool, so every build
attempt panicked again and the leader stopped producing blocks. Verified with a test, not on the
fleet. It now fails the call as a stack underflow; the non-empty and full-stack behaviour is
unchanged. This is a consensus change, but no committed block can have run this case because such
a block could not be built. Tests: `TestFusakaSlotNumEmptyStackUnderflows`
(`internal/vm/eips_amsterdam_test.go`) and `TestApplyTransactionFusakaSlotNumEmptyStack`
(`internal/slotnum_fusaka_test.go`).

### Closed after D2 (2026-10-29)

- **Spec BAL (7928)** is built and checked on the engine/newPayload path; all 102 Amsterdam
  blockchain failures pass. Details and commits in `eest-amsterdam-2026-10-29.md`.
- **Amsterdam block gas outside import.** The txpools (`3bd04949`, `130f04c6`), the payload
  builder (`afa0e0f9`), the miner (`16e39664`) and the sequential processor (`9c53b2c0`) use the
  EIP-8037 figures; the Block-STM processor falls back to sequential under Glamsterdam
  (`223ce0ef`). The dead pre-8037 7778 branch in `TransitionDb` is gone (`86e7db1e`).
- **Parallel-EVM replay** now checks the receipts root and logs bloom like A2 (`c1293637`).
  It still refuses post-Prague blocks, so the requests hash does not apply.
- **7702 authorization chainId above 2^64** is not a gap: the chain ID is a uint256 in the spec
  and in geth, and geth's pool does not limit it either.
- **EIP-2935 before Glamsterdam** stays a direct slot write, by decision. It matches the
  canonical contract and every stable and Osaka fixture; a system call would change the replay
  path of Ethereum mainnet and of N42 chains for no gain there. Amsterdam runs it as a system
  call (`8b3d8a8b`).

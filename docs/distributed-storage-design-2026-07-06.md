## 0. 定位与第一租户

做一张**内容寻址、可验证、按空间×时间计费**的存储网络,复用 N42 已有基建,而非从零造。

**第一租户 = 链自己的冷数据**(这是与所有竞品不同的冷启动方式):
- EIP-4444 冷段 body(~475GB,torrent 1-of-N 已实测 PASS)[已落地]
- DATC 静态档案(终局 ~0.7TB 不可变文件族)[构建中]
- 周度全态快照(~25GB/份,MPHF+zstd)[已落地]
- 块证明/witness 静态段 [已落地]

链自身的数据先把供给-需求两侧跑通,再开放第三方负载。

**可复用的家底** [已落地]:
| 组件 | 位置 | 用途 |
|---|---|---|
| CAS + IPFS/torrent/ed2k 桥 + 统一解析器 | internal/distributed/storage | 内容寻址与多协议检索 |
| provider 注册(stake/能力/信誉)+ 反向拍卖市场 + Verify-or-Slash | internal/distributed/coprocessor | 供给侧市场与罚没 |
| 三级验证(ZK / 乐观+押金+挑战 / TEE) | coprocessor/verification.go | 抗作弊仲裁分层 |
| BLS 聚合(512 委员会,114B/块) | crypto/bls + 重封管线 | 保管回执聚合上链 |
| WASM 燃料计量执行 + MapReduce | distributed/compute | 数据就地计算(增值服务) |
| 消息层(8-shard gossip、RLN 限速、E2E) | distributed/messaging | 挑战/回执/修复协调传输 |
| QMDB(O(changes) 承诺) | lib/qmdb | 计费表的廉价链上状态 |
| `ContentStoreTime` 分叉开关 | params.ChainConfig | 协议激活已预留位 |

## 1. 上传 [设计]

```
客户端: 切块(4MiB) → blake3 CID → RS(k,n) 纠删编码(按耐久等级)
       → 逐 provider 键控变换(防共享副本,见 §5) → manifest(merkle root)
链上:   StoreDeal tx { manifestRoot, size, durabilityClass, epochs, escrow }
分发:   反向拍卖选中 n 个 provider(按 region/价格/信誉) → 并行推送分片
确认:   ≥k 个 provider 的 BLS 存储回执聚合 → 一条 DealActive 记录上链
```

- 上传本体**不走链**(链只存 manifest+计费),数据走 messaging/torrent 通道
- 大对象(冷段级,GB-TB)直接复用 torrent swarm 路径 [已落地]
- 耐久等级示例:`standard` RS(20,30)(1.5× 开销)/ `archive` RS(20,36)+跨 3 区域 /
  `hot` RS + 边缘全副本

## 2. 计费:gas 与存储费分账 [设计]

两种费用**不混淆**:
1. **gas**:只为链上足迹付费(开单/续期/挑战/结算 tx),与普通交易同一套 gas 表;
   manifest 上链按字节计入 calldata gas
2. **存储费**:`cost = Σ_epoch bytes × unitPrice(region, class, epoch) + egress × retrPrice`
   - 预付进 escrow,**流式结算**(每 epoch 按回执解锁给 provider,Greenfield 式)
   - unitPrice 由反向拍卖发现(市场已有)[已落地],不由治理拍脑袋
   - 退租/数据丢失:未消耗 escrow 退还;丢失触发罚没赔付(§5)

## 3. 计量空间×时间 [设计]

- 计量单位:**Byte·Epoch**(epoch 对齐 hotstuff epochLength 或固定 1 天)
- 账本:QMDB 状态里每 deal 一个 meter(O(changes) 让百万级 deal 的每 epoch 更新可负担)
- 证据链:provider 每 epoch 交一份 BLS 签名的保管回执 → 委员会聚合(114B 模式)→
  一条聚合回执覆盖该 epoch 全部存活 deal → 链上只写聚合位图
- 计量作弊 = 回执作弊,由 §5 的抽查挑战兜底

## 4. 冗余、恢复、抗灾 [设计,部件已测]

- **纠删码**:RS(k,n),开销 n/k(1.5-1.8×),对照竞品全副本 3-25× 的成本优势
- **地理分布**:provider 注册带 region 标签,布置策略强制跨 ≥3 区域(archive 级)
- **修复市场**:epoch 回执缺失 → 分片进入 repair 队列 → 修复拍卖 → 新 provider 从任意
  k 份重建、提交重建证明、领取修复费(费用出自失职者被罚没的押金)——自愈闭环
- **抗灾底线**:冷段同时保留 torrent swarm 副本 [已落地,1-of-N 恢复实测 PASS];
  链上 manifest 永存,数据只要任意 k 份在,永远可重建
- 已有实测锚点:纠删/重建的成本模型可先用冷段 torrent 数据校准

## 5. 抗作弊 [设计,仲裁机制已落地]

| 攻击 | 防御 |
|---|---|
| 不存却收费 | 每 epoch 随机挑战:链上随机数(委员会 VRF)选 (deal, chunk, offset) → provider 限时返回 chunk 的 merkle 证明;超时/错误 → 计失职 |
| 共享副本(sybil 假冗余) | 每 provider 分片做**键控变换**(廉价 keyed XOF,非全量 PoRep 封装)→ n 份必须是 n 份物理数据 |
| 按需外部拉取(outsourcing) | 挑战响应延迟上限 Δ << 跨节点拉取时间 |
| 检索返回垃圾 | CAS 自验证(内容哈希即校验)[已落地] |
| 回执造假 | 回执须委员会抽样复核签名;争议走三级仲裁 |
| 争议仲裁 | 乐观+押金+挑战期 → 委员会复核 → ZK/TEE 终局 [已落地,coprocessor 三级验证] |
| 罚没与赔付 | Verify-or-Slash [已落地]:失职押金 → 修复费 + 用户赔付 |

设计取舍:**不用 Filecoin 式重型 PoRep**(封装硬件成本高、不利小节点),用
"键控变换 + 限时随机抽查 + 经济罚没"的轻量组合,换取低门槛供给。

## 6. 就近访问 + CDN [设计]

- **解析层**:统一解析器 [已落地] 返回按 RTT/region 排序的 provider 列表;
  客户端并行从最近 k 个拉分片
- **无信任 CDN**:内容寻址的根本红利——**任何 CDN/任何镜像都能服务,客户端验哈希**,
  CDN 无需被信任。热对象可直接推给传统 CDN 作快路径,验证在端上
- **检索市场与存储市场分离**(Filecoin 的教训):边缘节点缓存热 CID,按次收检索费
  (支付通道/微回执,messaging 层承载),不要求边缘节点参与存储质押
- **静态档案协同**:§0 的链上静态文件天生适合 CDN(不可变+自验证),历史 proof
  查询可全部下沉到边缘

## 7. 频度分层 [设计,比例有实测先例]

- 检索回执自然形成访问计数 → 自动升降级:
  - **hot**(边缘全副本+CDN)← 访问频度高
  - **warm**(RS 在线)
  - **cold**(RS + torrent swarm,响应秒-分钟级)
- 实测先例:链状态热数据 10%/2.3%(账户/槽),月活 3-4% —— 存储对象的频度分布
  预期同样长尾,hot 层只需覆盖个位数百分比即可吃掉绝大多数流量
- 降级不搬数据(RS 份保持),只撤边缘副本;升级由检索节点竞争性缓存自发完成

**各家最值得抄的一件事**:
- Storj:自动修复管线与审计经济学(成熟度最高)
- Walrus:2D 纠删把开销压到 ~4.5× 还能局部修复(Red Stuff 论文值得精读)
- Greenfield:流式支付的计费 UX
- Arweave:SPoRA 用"访问速度"激励副本分布(检索与存储激励合一的巧思)
- Filecoin:FIL+ 的需求侧补贴(冷启动),以及它检索市场失败的教训(我们用无信任 CDN 绕开)

**N42 的差异化立足点**:
1. 第一租户是链自己(冷段/档案/快照),供需冷启动不靠补贴
2. 存的东西大半**自验证**(CAS+静态 proof),检索侧天然无信任 → CDN 可白嫖
3. 仲裁/罚没/市场/聚合签名全部复用已落地组件,新增面小
4. 数据就地计算(WASM/MapReduce 已有)是竞品普遍没有的增值层

## 9. 开放问题与下一步 [设计]

1. 键控变换的具体构造与开销测量(目标:编码速度 ≥ 磁盘带宽,防外包延迟窗口可行)

4. 计费 meter 在 QMDB 的状态增长模型(百万 deal × epoch 更新)
5. MVP 切片建议:先用链自己的冷段做单租户闭环(上传→回执→挑战→罚没→修复全链路),
   不开放第三方,跑通经济学再开闸

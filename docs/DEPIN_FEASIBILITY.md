## 一、Karpathy AutoResearch 真实评估

**开源项目**：[github.com/karpathy/autoresearch](https://github.com/karpathy/autoresearch) (MIT 协议)

### 实际工作方式

给 AI Agent 一个可修改的 `train.py`（含小 GPT 模型 + 训练循环），Agent 自动迭代：
修改代码 → 训练 5 分钟 → 检查 val_bpb 是否改善 → 保留或丢弃 → 重复

### "超越 20 年调参" 的真实含义

Agent 在 ~100M 参数小模型上发现了 attention scaling 和 regularization 的疏忽，
叠加约 20 个微改进（weight decay 0.001、batch size 减半、transformer init scale 0.68x、Adam betas 调优），
训练到 GPT-2 级别的时间减少 11% (2.02h → 1.80h)。

### 扩展结果

- SkyPilot 16 GPU × 8 小时：910 个实验，验证集改善 2.87%
- Shopify CEO 复现：37 个实验一夜，0.8B 模型超越其手调 1.6B
- 收益递减明显：超参数 → 架构 → 微调 → 优化器，4 阶段后增益陡降

### 诚实评估

**这是自动化超参数/微架构搜索，不是自动化科学研究。**
适用于 ≤1B 参数的小模型调优，不适用于前沿模型训练。
与 N42 的关系：可作为分布式实验编排的消费场景，但非核心能力。

## 三、DiLoCo 算法——被忽略的关键缺陷

### 通信量减少 500 倍——已验证

| 规模 | 验证方 | 结果 |
|------|--------|------|
| 150M 参数 | Google DeepMind 原始论文 | 8 worker, 500x 通信减少 |
| 10B 参数 | Prime Intellect INTELLECT-1 | 跨洲训练, 400x 压缩, 96% 效率 |
| 72B 参数 | Bittensor Covenant-72B (SparseLoCo) | 146x 压缩, 94.5% 利用率 |

### 下游微调退化——严重问题

> **2025.11 论文 (arXiv 2511.13761)：DiLoCo 预训练模型微调后性能比标准训练差 5 倍**

| 指标 | DiLoCo | 标准训练 |
|------|--------|---------|
| 预训练 loss | ≈ 持平 | 基准 |
| MMLU (微调后) | 差 5x | 基准 |
| 指令跟随能力 | 严重退化 | 基准 |

根因："不可逆表征漂移"——各节点长时间独立优化后 embedding 空间发散。
切换回标准 DDP 后训练（混合方法）无法恢复质量。
**结构性问题，非超参调优可解。**

## 四、消费级 GPU 经济学

### RTX 4090 收入估算

| 场景 | 利用率 | 月毛收入 | 电费(美国) | 月净收入 |
|------|--------|---------|-----------|---------|
| 保守 | 35% (8h/天) | ~$294 | ~$38 | ~$256 |
| 中等 | 50% (12h/天) | ~$441 | ~$56 | ~$385 |
| 乐观 | 24/7 | ~$353 | ~$38 | ~$315 |

### 关键风险

- **GPU 硬件验证无解**：RTX 4090 无硬件级远程证明（H100 有 NVIDIA Attestation）
- io.net 的 180 万假 GPU 证明了 Sybil 攻击的现实威胁
- 利用率是决定性因素：Akash ~50%，io.net 不公开
- 购买 GPU 专用于 DePIN 经济上不明确；利用已有闲置 GPU 可行

## 五、Proof of Compute 技术分析

### Gensyn Verde 系统

工作流程：
1. 训练者运行计算，每 N=20 步存 checkpoint
2. 验证者独立运行相同计算（RepOps 保证可复现）
3. 争议时二分查找定位首个分歧操作
4. 仲裁者仅重执行该单一操作

### 开销

| 模型 | RepOps 验证开销 |
|------|----------------|
| Llama-1B 训练 | 67% |
| Llama-8B LoRA | 126% |
| DistilBERT 训练 | 312% |

### 核心限制

- **要求 FP32 精度**（现代训练用 BF16/FP16）→ 内存翻倍，吞吐减半
- 仅验证到 8B 参数
- 需至少一个诚实验证者
- 不同硬件间位级可复现性依赖 RepOps 控制浮点运算顺序——脆弱假设

**核心问题：ML 训练验证无法完全避免重执行。Verde 最小化了重执行量，但无法消除。**

## 七、建议

### 做什么

**推理 DePIN（推荐）：**
- 任务原子化（请求/响应），故障可重试
- 验证可行（确定性执行或输出比对）
- N42 已有 70% 基础设施
- 真实消费场景：N42 Chat AI、MCP 工具、AI Agent 推理

### 不做什么

| 方向 | 判定 | 理由 |
|------|------|------|
| 去中心化预训练 | ❌ | Covenant-72B 用 B200 集群非消费级；落后 SOTA 2 年 |
| 去中心化微调 | ⚠️ 谨慎 | DiLoCo 下游退化 5x；RTX 4090 仅 24GB (≤7B)；验证开销 67-312% |
| 独立造 DiLoCo 协调器 | ❌ | 对接 Prime Intellect/Bittensor 更实际 |
| 手机端 GPU 训练 | ❌ | Mali/Adreno 不适合 AI 计算 |
| 纯"挖矿"激励 | ❌ | 无真实消费者 = 空转代币 |
| AutoResearch 编排 | ⚠️ 可选 | 技术可行但价值不清晰；租 Lambda GPU 更简单 |

### 路线图

| 阶段 | 时间 | 内容 | 里程碑 |
|------|------|------|--------|
| **MVP** | 3 月 | 连接真实推理后端 → 预编译 0x0301 能执行推理 | 链上合约调用 AI 模型 |
| **Phase 1** | 3 月 | Provider 注册 + 链上 staking + 任务分发 | 外部 GPU 提供推理服务 |
| **Phase 2** | 3 月 | 硬件验证 + 支付通道 + SLA 监控 | 经济模型闭环 |
| **评估点** | — | 是否有真实算力消费者？用量是否增长？ | 决定是否继续投入 |

## 九、与 AutoResearch 的结合点

如果 N42 推理 DePIN 上线，可支撑以下 AutoResearch 工作流：

```
用户提交超参数搜索任务
  → N42 marketplace 分发到 GPU 节点
  → 每个节点运行 5 分钟实验 (train.py)
  → 链上记录实验结果 + Proof of Compute
  → 最优结果的贡献者获代币奖励
```

前提：推理 DePIN 基础设施已就绪 (MVP + Phase 1)。
价值：形成去中心化 AI 研究市场，非单纯算力出租。
优先级：Phase 2 之后评估。

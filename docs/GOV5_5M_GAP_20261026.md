## 2. Gov5's real critical chain (correction to the "root/write" reading)

The phases line shows root and the write hand-off are **not** the binding
chain any more: the child's ahead run starts at the parent's root
post-state hook and runs during the parent's ComputeRoot and hand-off
(`takeAfterHook` 57.5 ms, then `aheadWait` 19.7 ms). The loop that sets the
cycle is

```
hook(N) -> child available + launch (launchLag 7.8) -> aheadRun(N+1) 76.3
        -> take, block end + finalize before the hook: fPreHook 32.3 -> hook(N+1)
= 7.8 + 76.3 + 32.3 = 116.4 ms   (measured import-end interval p50 116.0)
```

aheadRun 76 = exec 45.7 + collect 14.9 + setup/prefill/prep ~15. The
equivalent loop in n42-rs is child start 1.8 + exec 30 + fold 2.2 + seal 4
= ~38 ms. The gap is not root or persistence; it is (a) ~16 ms of exec,
(b) ~45 ms of work between "transactions executed" and "the child may
read the post-state" (collect + block end + finalize + merge), and (c) ~8
ms of child availability.

## 3. CPU arithmetic: why 5M cannot be reached with 7 independent executors on this box

Gov5 at 1.24-1.35M uses ~24 cores per node, 7 nodes = ~170 cores plus 8
generators, on a 256-thread EPYC 9B45. Scaling linearly, 5M needs ~3.7x the
work: ~89 cores per node, ~620 cores fleet-wide. The box has 256 threads.
QS_MULTI_MILLION_DESIGN.md section 2 reached the same conclusion on
2026-10-09 ("At 3M TPS, exec + recovery replicated 7x needs ~840 cores") and
planned E=1 as **P2b**, "measured after P2a". P2a is done (vote on
availability, depth 2, stage pipelining); P2b was never built. n42-rs's own
history shows the size of the step: import-once moved its E=1 fleet from
1.11-1.28M to 1.59-1.61M (BD 10.76-10.78), and every later gain (to 5.2M)
was measured on E=1.

E=1 alone does not shorten the 116 ms chain: Gov5 is chain-latency bound,
not CPU bound, at 24 cores per node. E=1 frees ~140 cores (more Block-STM
workers, less DRAM/LLC contention) and is the precondition; the chain
must still fall from 116 to <= 40 ms at 200k-tx blocks (or <= 65 ms at
326k-tx full blocks).

## 4. Decisions (rule set) and recommendation

1. **E=1 benchmark mode (P2b).** Recommendation: build it now, report both
   numbers as QS_MULTI_MILLION_DESIGN.md section 3 already requires
   ("E=1 for the headline, 7x independent executors for the honest
   number"). Shape: one executor node imports every block; the six other
   validators run consensus with vote-on-availability, never execute, and
   take block N-k's deferred header fields (state root, receipts root,
   bloom, gas used) from the executor instead of their own lag executor.
   Their LagReady gate then tracks the executor's applied head. This is the
   n42-rs trust model (followers trust the shared layer) and must stay a
   bench-only switch, never a production default.
2. **Block shape.** Fill to 100% of the gas ceiling, or raise the fill to
   200k like n42-rs, so per-block fixed costs (hdr 3.5, launch 7.8,
   fPreHook) amortise over more transactions.
3. **Signature rule set.** secp256k1 stays the honest ETH-compatible
   number; the 5M comparison with n42-rs is only like-for-like with Ed25519
   0x50 transfers and gateway-attested frames (the Gov5 5M worktree already
   carries an offline Ed25519 carrier, `common/transaction/alt_sig_*.go`,
   2fc1089f/c7f450f5). Recommendation: keep secp256k1 + committee for the
   honest line, add the Ed25519 rule set only for the E=1 headline.

## 5. Order of work for the chain itself (after E=1)

1. Child reads the parent's executed write set directly (n42-rs output
   shards / X19 merge elision): publish the snapshot from Block-STM's final
   versions plus fee and system-call deltas, before collect and the
   block-end finalize; collect, receipts, finalize and merge leave the
   chain. Target: the 45 ms between exec end and hook to <= 8 ms.
2. Exec 45.7 -> <= 30 ms: interpreter-free transfer path over the whole
   block (QS P3 gate: >= 100k tx/s/core), with the freed E=1 cores.
3. Child availability (launchLag 7.8, childAvailCheck 23): start at
   availability, with depth-2 leader layering as n42-rs `N42_LEADER_LAYERS`.
4. Only then root (19) and writer (handWait 13.7) become visible.

## 6. Ownership on the shared box

QS (N42-gov5 session) owns the qs fleet rounds and the per-node chain;
Gov5 Codex owns the strict shared-owner lane (`internal/sharedexec`, durable
contract). This note proposes E=1 under the qs fast path as a separate,
switch-gated branch (`n26/gov5-e1`) whose fleet runs go through the normal
FIFO gate. No claim, request or run is filed by this note.
